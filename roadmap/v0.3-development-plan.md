# AutoCast v0.3 Development Plan

## Objective

Make AutoCast credible as a market-ready AI SDLC harness standard by strengthening what is already differentiated and closing the gaps exposed by the Nexu benchmark.

## Product Position

AutoCast should be known as:

```txt
The auto-standard framework for safe AI-assisted software delivery.
```

That means AutoCast must be practical, measurable, secure, and tool-agnostic.

## Strategic Focus

## Strengths To Double Down On

- Minimum intake questions.
- Risk-based workflow routing.
- SDLC-specific workflows.
- Independent judges.
- Security and compliance language.
- OpenCode, Claude Code, and Cursor adoption path.

## Weaknesses To Minimize

- No executable runner yet.
- Limited eval dataset.
- Limited context and memory policy.
- Security is partially policy-based instead of enforcement-backed.
- Adapter installation is still manual.
- No public benchmark results yet.

## Version Target

`v0.3` should not be a massive platform. It should be the smallest version that proves AutoCast works repeatedly.

Target promise:

```txt
Give AutoCast a software task and it will ask the minimum necessary questions, choose the right workflow, apply security gates, select judges, and produce evidence that the task was handled correctly.
```

## Workstreams

## 1. Adapter Packs

Goal: make AutoCast easy to install into OpenCode, Claude Code, and Cursor.

Deliverables:

- `adapters/opencode/install.md`.
- `adapters/claude-code/install.md`.
- `adapters/cursor/install.md`.
- Ready-to-copy agent files for router, reviewer, correctness judge, test judge, and security judge.
- Example command prompts for each tool.
- Permission recommendations for each tool.

Acceptance criteria:

- A user can install the basic adapter in under 10 minutes.
- Judges are configured read-only where the tool supports it.
- Security-sensitive workflows are documented for each tool.

## 2. Router And Intake

Goal: make route selection precise and measurable.

Deliverables:

- Structured route decision schema.
- Expanded `intake/minimum-questions.md` with examples.
- Route examples for low, medium, high, and critical risk.
- False-escalation guidance to avoid overusing `critical-change`.

Acceptance criteria:

- Route selection accuracy reaches 90% on internal eval cases.
- Critical escalation recall reaches 95%.
- The router asks no more than 2 unnecessary questions per task on average.

## 3. Security Enforcement Layer

Goal: move security from checklist-only to gate-driven behavior.

Deliverables:

- Permission classifier prompt.
- Tool action risk taxonomy.
- Pre-execution decision format: `allow`, `ask`, `deny`.
- Sandbox expectations by route.
- Security evidence report template.
- Supply-chain checklist for dependency and CI changes.

Acceptance criteria:

- High-risk seeded security issues are detected at least 90% of the time.
- Secret exposure is always blocking.
- Auth, authorization, CI/CD, payment, production data, and crypto changes route to `critical-change`.

## 4. Judge System

Goal: make judges consistent and useful instead of subjective.

Deliverables:

- Improved judge prompts with strict output format.
- Rubric thresholds per route.
- Judge calibration cases.
- Examples of good and bad judge reports.

Acceptance criteria:

- Correctness judge catches at least 80% of seeded blockers.
- Test judge rejects missing verification for important behavior.
- Security judge rejects high or critical risk without mitigation.

## 5. Eval Dataset

Goal: prove AutoCast's claims with repeatable tests.

Deliverables:

- 10 `fast-lane` evals.
- 15 `standard` evals.
- 15 `secure-change` evals.
- 15 `critical-change` evals.
- 10 adversarial prompt injection evals.
- Scoring guide for route, judge, security, and workflow quality.

Acceptance criteria:

- Evals can be scored manually at first.
- Every eval has expected route, expected judges, and expected security classification.
- Results are recorded in a benchmark report.

## 6. Context And Evidence

Goal: reduce context drift and make results auditable.

Deliverables:

- Context priority policy.
- Evidence log template.
- Run summary template.
- Rules for what should never enter context.
- Guidance for long-running tasks and context reset.

Acceptance criteria:

- Every workflow has a clear evidence output.
- Sensitive data is excluded from context by default.
- Judges receive diffs and task briefs rather than broad noisy context.

## 7. Optional Local Runner

Goal: create just enough executable glue to make AutoCast measurable.

Deliverables:

- CLI concept: `autocast init`, `autocast route`, `autocast eval`, `autocast report`.
- Config loader for `autocast.config.yml`.
- Route scoring from eval fixtures.
- Evidence folder convention.

Acceptance criteria:

- Runner is optional and does not replace existing coding agents.
- Runner can score route-selection evals locally.
- Runner can generate a task brief from intake answers.

## Proposed Timeline

## Phase 1: v0.2 Foundation

Focus: adapters, examples, security classifier, better docs.

Deliverables:

- Install guides.
- More agent files.
- More examples.
- Permission classifier prompt.
- 20 eval cases.

Exit criteria:

- AutoCast is easy to install manually.
- AutoCast can be used consistently in a real project.

## Phase 2: v0.25 Evaluation

Focus: measurable quality.

Deliverables:

- 40 eval cases.
- Judge calibration examples.
- First benchmark result document.
- Security false-positive review.

Exit criteria:

- AutoCast can demonstrate measurable routing and judge quality.

## Phase 3: v0.3 Local Harness

Focus: optional runner and public credibility.

Deliverables:

- Optional CLI or script runner.
- 60+ eval cases.
- Evidence output convention.
- Public benchmark report.
- Polished docs and examples.

Exit criteria:

- AutoCast can be presented as a serious open source harness standard.

## Market Readiness Checklist

- Clear README.
- Clear install path.
- Clear positioning.
- Security story is credible.
- Benchmarks exist.
- Evals exist.
- Examples exist.
- Adapters exist.
- License exists.
- Contribution guide exists.

## Non-Goals Before v0.3

- Do not build a hosted SaaS.
- Do not compete directly with OpenCode, Claude Code, or Cursor.
- Do not build a full managed-agent runtime.
- Do not add complex dependencies before evals prove the need.
- Do not claim perfect security.

## Key Product Principle

AutoCast should make the safe path the fast path.
