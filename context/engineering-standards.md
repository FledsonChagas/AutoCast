# Engineering Standards

## Code Style
Follow the existing project style. Do not introduce new patterns without a clear reason.

## Testing
Prefer tests that prove behavior over tests that mirror implementation.

## Dependencies
Do not add dependencies unless the task cannot be reasonably solved with existing tooling.

## Backward Compatibility
Do not add compatibility layers unless there is persisted data, shipped behavior, external consumers, or an explicit requirement.

## Documentation
Document decisions, not obvious code.

## Security
Apply least privilege, secure defaults, input validation, safe error handling, and secrets hygiene.
