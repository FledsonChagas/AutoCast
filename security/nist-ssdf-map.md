# NIST SSDF Map

Map AutoCast evidence to NIST Secure Software Development Framework practices.

## PO: Prepare The Organization

- `context/engineering-standards.md` defines secure development expectations.
- `security/security-baseline.md` defines baseline controls.

## PS: Protect The Software

- Secrets hygiene is required.
- Dependency changes require justification.
- Build and CI/CD changes require critical route review.

## PW: Produce Well-Secured Software

- Threat modeling is required for sensitive changes.
- Security judges review trust boundaries and common weakness classes.
- Tests and verification are required evidence.

## RV: Respond To Vulnerabilities

- Bugfix workflows require root cause and regression evidence.
- Security findings must be recorded as blocking or non-blocking.
